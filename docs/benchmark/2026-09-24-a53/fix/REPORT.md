# 再測定（普段どおりの AI が書いた HTML 10 件 / 診断だけで最小修正）

- CLI: `R/bin/shashoku`（既定フォント埋め込み）。ガイドは **hint が指した節だけ**読んだ（§4.3 のみ）。
- 往復の定義: 1 往復 = そのとき出ている診断を全部直して描き直すこと。`rN.html` が N 回目の修正後、`rN.json` はその診断。`r0` は無修正の入力。
- 盲検は守った（リポジトリ・R の外・他エージェントの出力は読んでいない）。拒否された操作は **なし**。

### 学習の持ち越しについて（往復数の読み方）
同じセッションで 10 件を順に直したので、前の case で学んだことは次の case に持ち越した。
具体的には (a) `body{}` を `.page` の div に移す（case01 で発覚）、(b) `display: inline-block` は
「flex の親 + `flex: none` の子」に置き換える（case03 の hint で学習）、(c) `opacity` は削る、の 3 つを
case04 以降で先回りして直している。先回りしなければ case02/04/08/09 は **それぞれ +1 往復**だった。

## 2. 診断に出ない壊れ方（case ごと）

1. **case01 — `body{}` のスタイルが丸ごと消える。** `<body>` が unsupported-tag なので指示どおり外すと、
   `body { background; padding; font-family; color }` が誰にも当たらなくなる。エラーも警告も出ず、
   上下の余白 40px と背景色と本文色が黙って消えた（左右の余白だけは `margin: 0 auto` のおかげで残るので気づきにくい）。
   **`<body>` を外せと言う診断が、そのスタイルの行き先を言わないのが原因。** 10 件中 7 件が同じ形の HTML なので影響は大きい。
2. **case02 — stretch で伸びた flex アイテムの中では中央揃えが効かない。** 親の `align-items: stretch` で
   329px に伸びた `.arrow` の中で `align-items: center` を指定しても、中の 2px の線は箱の**上端**に置かれた
   （`flex-direction: column` + `justify-content: center` でも同じ。`height: 100%` は unsupported-value）。
   伸ばされた後の高さが内側のレイアウトに伝わっていないように見える。矢印 4 本がカードの上辺に張り付き、
   フロー図として読めなくなっていた。`height` を数値で書くしか回避策が無く、その数値は `--dump-stage box` で測るしかない。
3. **case02 — `flex: 1 1 0` の兄弟で padding の有無が違うと外形幅がそろわない。** content-box なので
   padding を持つ `.step`（138px）と持たない `.worker-col`（108px）で列幅が 30px ずれ、ワーカー列だけ明らかに細くなった。
   box-sizing の hint は「`width`/`height` から引け」としか言わないので、**幅を書いていない flex 項目には手がかりが無い**。
4. **case03 / case05 / case07 / case10 — 明朝が黙ってゴシックになる。** `font-family` に無いファミリを書いても
   警告は出ない。短歌（case10）と読書メモ（case05）は明朝が designs の主役なので、絵としては別物になる。
   豆腐は警告するのに、**ファミリの取りこぼしは警告しない**。
5. **case10 — 縦書きの列に 1 文字入らない。** 800×1200・`height: 880px` の列に Chrome は「立ちつくし」まで収めるが、
   shashoku は 1 文字手前で折り、2 列目の頭に「し」だけが残った。はみ出しではないので診断は出ない。
   `height` を 900px にして解決したが、**これは絵を見ないと分からない**。
6. **case08 / case03 — `overflow: hidden` を落とすと角丸の中から子がはみ出す。** 下記 5 節。

## 3. hint の評価

### 効いた
- **`box-sizing`**（「content-box only: subtract padding and border」）: 10 件中 8 件で使い、迷わなかった。
  case05 では引き忘れて 112px はみ出したが、**`content-overflow` の警告が位置と px 数を出したので 1 往復で直せた**。
  この 2 つ（hint と警告）の組み合わせがいちばん効いた。
- **`grid`**（「1 行の等幅なら flex + `flex: 1 1 0`」, §4.3）: case08 の 3 列指標がそのまま置き換わった。迷いゼロ。
- **`min-height`**（「親が stretch の flex なら落とせ」）: case02 の `.step` はまさにその条件で、落として問題なかった。
- **`inline-block`**（「flex の親 + `flex: none` の子」, §3-(4)）: case03 の label、case08 の pill で有効。
  「flex コンテナの中なら既に flex 項目」という前半のおかげで、case07 の `inline-flex` も即 `flex` にできた。
- **`-webkit-writing-mode` → 接頭辞を外せ**: 一読で直せた。
- **`background-clip: text` の注意つきグラデ hint**: case06 で「色も落とすと文字が消える」と先に言われたので、
  透明文字で見出しを消さずに済んだ（**これが無ければ絵が壊れていた**）。
- **`position` → flex を使え**: 方針としては正しく、case05/case10 の絶対配置は flex で置き換えられた。

### 誤解を招いた・足りなかった
- **`writing-mode` の hint が `ARCHITECTURE.md A1` を指す**（case10）。HTML を書く側はそのファイルを読めない。
  ガイドには §4.10「縦書き」があるのだから、そちらを指すべき。実際の書き換え（絶対配置 3 か所を縦書き flex に組み直す）は
  hint の外にあり、**縦書き + flex の主軸/交差軸の向き**が分からないと手が出ない。ここは運良く 1 往復で通ったが、
  10 件の中でいちばん危なかった。
- **辺ごとの border の hint が「区切り線か、枠の一辺か」の 2 択しか示さない**（下記 4 節）。
  実際には 3 件が「アクセントの帯」で、どちらでもない。
- **`unsupported-layout`（inline 要素に箱プロパティ）が 1 プロパティずつしか出ない**（case04）。
  `border` → `border-radius` → `padding` と 3 往復に分かれた。同じ要素・同じ理由なのだから一度に出してほしい。
  **「一度に全部」の原則がここだけ破れている。**
- **`image-not-found` に hint が無い**（case06）。`--image` で渡した名前（`avatar`）を教えてくれれば 1 往復減った。
  「`<img src>` には `--image` の**名前**を書く（ファイル名ではない）」は間違えやすい。
- **`transform` に hint が無い**（case09）。回転の代替が無いこと（＝飾りを諦めるしかないこと）を書いてほしい。
- **`object-fit` / `-webkit-font-smoothing` / `letter-spacing` 以外の細かいプロパティに hint が無い**のは実害が小さい（削るだけ）。
- **無くて困った hint**:
  1. `<body>` / `<html>` を外すときに **`body{}` のスタイルをどこへ移すか**（実害がいちばん大きい）。
  2. **stretch された flex アイテムの中では中央揃えが効かない**こと（そもそも仕様として直すべきかもしれない）。
  3. **`flex: 1 1 0` の兄弟は padding が違うと外形幅がそろわない**（box-sizing の hint の続き）。
  4. **font-family のファミリが見つからないときの警告**（hint 以前に診断が無い）。

## 4. 辺ごとの border（`border-top` 等）

| 使われ方 | 件数 | 取った対応 | 用途を満たせたか |
|---|---|---|---|
| 箱と箱の間の区切り線 | 12 か所（case01×6・02・03・04×2・06・07・08×2・09×2） | 高さ 1px（2px）の div | **満たせた**。レイアウトも 1px ずれるだけ |
| 表の列の間の縦罫 | 18 か所（case01） | 幅 1px の div を行に挿入 | **満たせた**（ただし HTML が 18 行増える） |
| 箱の一辺のアクセント帯 | 3 か所（case02 上 4px・case03 左 4px・case07 左 4px） | hint の「枠の一辺 → 削る」に従って削除 | **満たせなかった**。3 件とも「その帯が意匠の要」で、消すと別のデザインになる |

アクセント帯は「区切り線」でも「枠の一辺」でもない第 3 の用途で、hint はこれを想定していない。
`.sp { border-left: 4px }` のような形は、**箱を flex 行にして先頭に 4px 幅の div を置く**（padding は内側の div に移す）
という定石が書ければ再現できる。今回は「最小修正」の規則に従って削ったが、実運用では書き直したくなるところ。

## 5. box-sizing と `overflow: hidden`

- **box-sizing の引き算をした箇所: 合計 26**（case01 4 / case02 3 / case03 1 / case04 1 / case05 4 / case06 4 /
  case07 2 / case08 0 / case09 1 / case10 6）。`* { box-sizing: border-box }` は 10 件すべてに入っていた。
  引き算そのものは機械的で難しくないが、**引き忘れは case05 のように 112px のはみ出しになる**（警告で拾えた）。
  難しいのは引き算ではなく、**幅を書いていない flex 項目**（case02）のほうだった。
- **`overflow: hidden` を落として角が崩れた件数: 2 件**（case03 の上端グラデ帯、case08 の濃紺ヘッダ）。
  どちらも「角丸カード + 端まで届く色の子」という同じ形。`overflow` は unsupported-property として
  hint 無しで消えるだけなので、**角が四角くなることは絵を見るまで分からない**。
  ガイド §3-(5)「border-radius は中身をクリップしない」は知っていれば予測できるが、診断からは辿れない。
  残り 5 件（case01/05/06/07/10）は `overflow: hidden` があっても角に届く子が無く、被害なし。

## 6. まとめ（測った数字）

- 10 件すべて PNG になった。**exit 0 まで中央値 2 往復（最大 4）、絵が正しくなるまで中央値 2 往復（最大 4）**。
- 往復が増えた原因は 3 つだけ: (a) inline 要素の違反が 1 つずつ出る（case04 で 3 往復）、
  (b) 画像名の勘違い（case06 で 1 往復）、(c) 絵を見ないと分からない壊れ方（case01/02/10 で計 5 往復）。
- 絵の作り直しが必要になった case は 0。10 件とも「診断が指した箇所を直す」だけで版面は保てた。
- 残った品質差は **絵文字の豆腐（4 件）** と **明朝が出ない（4 件）**、**グラデ・影・破線・回転・アクセント帯が消える**こと。
  これらは往復では減らない（仕様の制約）。
