## 診断に出なかった壊れ方（3 件）

1. **case02: 注記の箱が ワーカー の箱より 8px 右にずれた。**
   §4.7 の手順どおり spacer を `3×160 + 3×24 + 6×8 = 600px` と計算したのに、注記の行
   （`.notes`）自身に `gap: 8px` を書いていたので、spacer の直後にもう 8px 入った。
   エラーも警告も 0 件。`--dump-stage box` の `rect` 先頭（620 対 628）で気づいた。
2. **case02: 段の箱の高さが不ぞろい。** §4.13 の定石どおり `align-items: center` を書いたため、
   説明が 1 行の段は 99.1px、2 行の段は 118.3px になり、図として締まらない。診断 0 件。
3. **case07: 箇条の丸が名前の中心より約 10px 上。** ルビのある行は行ボックスが**上に**約 15px
   広がるので、§4.4 の式（ルビ無し前提）で出した `margin-top` では合わない。診断 0 件。

いずれも「エラーが無いことは絵が正しいことを意味しない」（§6.3-5、§6.4）の実例で、
ガイドの警告どおりだった。**3 件とも `--dump-stage box` の数字で原因を特定でき、1 回で直せた。**

## ガイドの不足（実際に困った順）

1. **§4.7 の spacer の数え方に「注記の行自身の `gap` も足し算に入る」が無い。**
   例の `.notes` が `gap` 無しなので、`gap` を付けた瞬間に静かにずれる。
   「spacer を使う行には `gap` を書かない（書くならその分を引く）」の 1 行が欲しい。
2. **§4.4 の丸の `margin-top` の式が、ルビのある行では成り立たない。**
   §4.11 に行の高さの式（`font-size × max(line-height, A + line-height ÷ 2)`、A ≒ 1.45）は
   あるのに、§4.4 と結び付いていない。ルビ付きの行に丸やアイコンを合わせる式が欲しい。
3. **§4.13 の flow の定石が `align-items: center` 固定で、段の高さがそろわない。**
   そろえたいときの形（`align-items: stretch` にして、矢印を入れ子 flex の
   `align-items: center` / `justify-content: center` で中央に置く）が書かれていない。
   矢印の中に素のテキストを置いてよいか分からなかったので `div` で包んだ（結果は正しく出た）。
4. **交差軸の `margin: auto` が使えるか分からない。** §2.3 は「横並びの子に `margin-left: auto`、
   縦並びの子に `margin-top: auto`」だけなので、`flex-direction: column` の子を
   `margin-left: auto` で右に寄せてよいのかが読み取れず、flex 行で包む形に逃げた（case05）。
5. **縦書きで flex 項目の交差軸（字送り方向）が既定の `stretch` で紙面いっぱいに伸びることが
   §4.10 に書かれていない。** 歌の箱は本文の実寸 992px に対して 1008px になっていた
   （`--dump-stage box` で確認）。今回は影響しなかったが、箱の端を基準に何かを合わせると 16px ずれる（case10）。

補足（困りはしなかったが気づいた点）:

- §4.9 の OG の骨格（タイトルに `flex: 1 1 0`）は、タイトルが短いとタイトル下に大きな空きが出る。
  「中央に置きたいならその箱に `justify-content: center`」の一言があると親切（case06）。
- 数字 + 単位（`42 件`）を 1 行で組む形は §3-(2) の「`font-size` の違う `span` はベースラインで
  揃う」から導けた。定石としては無いが、書いてあったので迷わなかった（case08）。

## hint の評価

**エラーが 1 件も出なかったので、hint は 1 度も表示されていない**（`hints_used` は全件 空）。
誤解を招いた hint も無い。今回の測定では、hint の質ではなく
**「ガイドを読んだだけで最初から範囲内の HTML が書けるか」**が測れた形になる。

hint の代わりに効いたのはガイドの次の記述で、これが無ければ確実に往復していた:

- §3-(1) content-box の引き算（1200×630 → `1072×502 + padding 64`）— case05 / 06 / 07 / 10 で使用
- §3-(3) flex の直接の子は block 化される — pill / バッジを `div` で書く判断が即決できた
- §3-(5) `border-radius` は中身をクリップしない — case01 で見出し行に色を敷くので
  表の `border-radius` を**最初から書かなかった**（書いていたら角から四角く出ていた）
- §2.4 の記号一覧 — `→` `▲` `※` `−` `±` `――` を安心して使え、豆腐が 1 つも出なかった。
  絵文字を使わない判断もここで決まった
- §5 の「日本語の組版で気をつけること」— `letter-spacing` を「第 12 回」に使わない（case07）
- §4.10 の縦書きの軸の表と 2 つ目の例（右端に題・左端に署名）— 歌を右端・作者名を左端に置く
  配置がそのまま当てはまり、軸を考え直さずに済んだ（case10）

## 所感

- **10/10 が 1 回で通り、警告も 0。** 対応表（§2）・落とし穴（§3）・定石（§4）・代替表（§5）を
  先に読めば、対応外のプロパティを書きたくなる場面がそもそも来ない。
  `<table>` `<ul>` `position` `box-shadow` `inline-block` は一度も書かなかった。
- 残る失敗は**全部「位置の数え間違い」**で、診断には出ない。裏返すと、
  `--dump-stage box` が実質的な検算手段になっている。§4.7 は既にこれを勧めているが、
  **`gap` / ルビ / `align-items` が絡むと手計算が合わない**ので、
  「spacer とアイコンの位置は必ず `--dump-stage box` で検算する」を §4 全体の注意に
  格上げしてもよさそう。
- 組版そのものは 10 件とも問題なし。行頭の句読点・閉じ括弧は 1 件も無く、和欧混植の空き、
  ルビの配り、縦書きの字の向き（長音符を含む）、`――` の連結、いずれも目視で違和感が無かった。
- 唯一 usable を 4 にしたのは case10。歌を右端・作者名を左端に置くと（依頼どおり）中央が
  約 515px 空くためで、エンジン側の問題ではない。縦書きは正しく出ている
  （1 行 32 字、長音符も縦向き、作者名は左端・下端、寸法 800×1200 を `--dump-stage box` で検算）。
  §4.10 の 2 つ目の例（「右端に題・左端に署名」）がこの依頼にそのまま当てはまり、
  縦書きの軸を考え直す必要が無かったのが大きい。
