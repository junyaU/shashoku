データストア比較（技術選定資料）

RDB / KVS / ドキュメント DB の 3 つを、5 つの観点で比べたもの

項目
RDB（PostgreSQL）
KVS（Redis）
ドキュメント DB（MongoDB）
得意なデータ
関係が決まった構造化データ。結合や集計を伴う検索に強い。
小さな値の出し入れ。一覧やカウンタを即座に返す用途。
形の揺れる文書。項目が増えても移行なしで書ける。
トランザクション
複数行・複数表にまたがる ACID を標準で満たす。
複数コマンドをまとめられるが、途中まで実行して戻せない。
1 文書なら原子的。複数文書は版と構成に依存する。
スケール
基本は垂直。読み取りはレプリカを足して横に伸ばせる。
シャーディングで水平に。ただし容量はメモリ次第。
シャードキー次第で水平に伸びる。設計の勘所が多い。
運用の手間
バックアップと版上げの手順が確立。社内の知見も多い。
設定は軽いが、永続化と退避の方針決めが必要になる。
索引の設計を誤ると急に重くなる。監視の目が要る。
うちでの用途
受注・請求など、整合性が最優先の基幹データを置く。
セッションと API のレート制限、集計結果の一時置き。
監査ログと外部 API の応答を、形を変えずに保存する。
