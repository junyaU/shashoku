## 2. 診断の質（V2-fix の 299 件）

- **位置**: 299 件すべてが直すべき宣言・タグを指していた
- **効いた hint**: `box-sizing` の「padding と border を引く」（10/10 件に `* { box-sizing: border-box }` があり、この 1 行で全寸法の引き算が決まった）、ベンダー接頭辞、`writing-mode` の本文（直し方を含む）
- **効いた警告**: `content overflows the canvas by 198.0px (left)`（case10）。辺と量から縦書きの寸法計算の誤りが一発で特定できた
- **誤解を招いた hint**: inline への箱プロパティの「宣言を削る」（8 件。全部 pill / タグ / バッジで、削ると設計が壊れる。正解はガイド §3-(4) の flex の親 + `flex: none`）、`min-height` の「固定 height に」（親が stretch のときは削るのが正解）
- **hint が無くて困ったもの**: 辺ごとの `border`（10 件中 6 件で登場。「高さ 1px の div」はガイドから）、gradient の `unsupported-value`（「単色に」の 1 行）、`display: grid` + `grid-template-columns`（`flex: 1 1 0` が `1fr` 相当）
- **重複**: `border-width` の `unsupported-layout` が同一位置・同一文面で 2 件
- **段の隠れ**: `css-parse` で規則ごと落ちると中の宣言は検査されず、セレクタを直した次の往復で初めて出る

## 3. 診断に出ない壊れ方（次の検出候補）

| 事象 | 件数 | 何が起きたか |
|---|---|---|
| 内容依存の高さの列 flex の中で、子の `flex: 1 1 0` が高さ 0 に潰れ、内容が PNG から消える | case02（+3 往復）、case04 | exit 0・errors 0・warnings 0 |
| 縦書きで `padding-top` を取りすぎ、残りの字送りに収まらず署名が 2 列に割れる | case10（+2 往復） | 紙面の外には出ないので `content-overflow` は出ない |
| 高さ固定の紙面で下に大きな空きが残る（余白の偏り） | V2-guided case07 | exit 0。usable 4 の唯一の減点 |

いずれも「箱からのはみ出し・箱の潰れ」の族で、A46 が対象にしなかった `BoxOverflow`（§3.8）の実例。関門で優先度を判定する材料。

## 4. ガイドの不足（V2-guided が自力で埋めた穴）

縦書きの行送り方向（左右）の位置決め／「縦中央に置きつつ別の要素を下端に固定する」定石（引用カードの基本形）／
`<img>` は flex の子に直接置ける（§3-(3) と §4.12 が矛盾して読める）／flex の入れ子（矢印の縦中央、タグ列）／
既定フォントに入っている記号の一覧（`−` `±` `–` `→` `――` は全部出た）／ルビのある行の高さの式／空セルの高さ（`&nbsp;`）／
注記の spacer 幅の手計算が重い。V2-fix からは: 矢印が「→」の文字になると「破線の枠は…」のような凡例の文言と絵が食い違う／
`--font` を渡さないと明朝・等幅が出ない。

## 5. 読み方の限界

- 書き手・直し手はどちらも Opus 1 モデル。content-box の逆算や spacer 幅の手計算を自力でやっている。小さいモデルで同じ数字が出るとは限らない
- 依頼は既知の 15 件（10 件は前回と同じ）。未知の依頼への一般化は未検証
- 人の時間は測っていない（往復 = CLI 実行 1 回）
- 「エラー 0 = 絵が正しい」ではない（3 の実例）。strict の成功は「対応範囲の中で、検出対象の検査を満たした」まで（DESIGN.md §3-6）
